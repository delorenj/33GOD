## 2. The race (the blocker), reproduced twice

### 2.1 Codex on Darwin, `collect_runtime_generations`

Script `/tmp/w61a-race.py` on the Mac (kept at `/tmp/mirror-w69/W6-1a-verify.codex-race.py` on big-chungus). It wraps `probe.unused`: calls the real scan, then starts a child that opens `gen/held`, returns the idle list, and lets the collector continue. State root `/tmp/w61a-race-state`.


### 2.2 Driver on Linux, `collect_generations` (pin checkout `/tmp/w61avd/hermes`, throwaway `HERMES_HOME`)

Script `/tmp/w61avd/race_deps.py`. `control`: child holds a file in the old generation before the scan. `race`: child starts after the scan (injected by wrapping `unused`). Re-run for this evidence:

```
control: child live=True probe now says in use=True removed=False dir exists=True
race: child live=True probe now says in use=True removed=True dir exists=False scan took 0.283s
scratch removed: True
```

So the guard keeps what it can see and the window is the scan-to-delete gap (0.28 s on Linux, 0.16 s of probe time on the Mac). The orphan collector re-checks under the install lock but the re-check is leases only, so an external, unleased user (an MCP server, a launchd PATH entry) is invisible to it. All three collectors share the pattern.

### 2.3 Suggested fix (not tested, driver's reading)

Two-phase collect: atomically rename the candidate to a quarantine name on the same filesystem, re-probe with the new path (open files and cwd now show the renamed path; a process that tries to start via the old path gets ENOENT instead of losing files mid-run), then `rmtree` if still idle or rename back. Add a regression test that starts a process between inspection and removal (the two scripts above are the shape). Then re-review and re-pin.
