## 3. The duplicate-send risk, and the upstream fix

`reportctl distribute` was not idempotent: every call re-sent every target. A Candybar retry, a misfire after a late fire, a manual run, or a recovery pass would each put a second copy in Damian's inbox. Candybar's own idempotency key does not help once a run is invoked twice.

`2e2928d` adds an **opt-in** `--once` (and `DDR_DELIVER_ONCE`, read by `nightly.sh` from the host overlay). Unset, nothing changes: no receipts file is read or written. With it:

- under a per-date `flock` it reads `artifacts/<date>/deliveries.json` and skips any target with a successful receipt for the published generation, reported as `already_delivered` and counted as delivered;
- each attempted target is recorded the moment it returns, so a crash on a later target cannot erase an earlier delivery;
- mail carries `Idempotency-Key: delonet-daily-report/<date>/<generation>/<target>` (Resend dedupes for 24 h, covering a send that succeeded just before a crash);
- a failed target is retried; a new generation (a re-run of the day) is delivered anew; a dry run records nothing;
- an unreadable, malformed or unwritable ledger fails the command (exit 2 or 3). It is never read as "nothing delivered", because that reading is a duplicate send.

Review: Codex round 1 FAIL (5 findings: no lock, per-target recording, Idempotency-Key, strict ledger validation, nightly fail-closed on a bad overlay value), all fixed; round 2 **PASS** (it also independently ran 4 concurrent processes, an abrupt exit between targets and a real filesystem write denial). Tests: new `test_deliver_once.py` plus `test_host_overlay.py` additions, 57 passed focused, also with `DDR_DELIVER_ONCE=1` in the outer environment; full delonet-daily-report suite through `heavy`: 533 passed, 820 subtests.
