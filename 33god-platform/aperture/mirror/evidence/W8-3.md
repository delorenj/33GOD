## 2. The daprd / dapr-placement note: no bump was needed

The task said to bump `dapr-placement` first and then the sidecars, because "the enricher's daprd crash-looped on 1.13.0". Read-only checks on big-chungus and the source show this does not apply to W8-3's service:

- `bloodbank/services/turn-enricher/main.py` is a plain nats-py **core** subscriber. It has no Dapr client and no sidecar. Its compose file has one service. Jarad's live `bloodbank-turn-enricher` container on big-chungus is the only container in its compose project (`docker ps --filter label=com.docker.compose.project=bloodbank-turn-enricher`); the `enricher-daprd` running there belongs to the separate embeddings service.
- The crash-looping `enricher-daprd` belongs to the other service, `33god-platform/enricher` (the embeddings FastAPI service behind daprd 1.13.0). That image is amd64-only and 6.5 GB, and it is not part of W8-3.
- The root cause of the 1.13 crash was a zombie JetStream consumer: a host crash zero-filled `o.dat` and Dapr 1.13 nil-pointer-panicked on it. The bus's `init.sh` now reaps zombie consumers (`reap_zombie_consumers`); the Mac's `bloodbank-nats-init` ran it and exited 0.

Decision: no placement or sidecar change. Candystore's daprd stays on 1.13.0 (ratified in W3-1). PLAN.md rows 39 and 53 were corrected (section 10). Proof that nothing moved: section 8 (container start times and restart counts identical before and after).

### 3.3 The Jev request route

`jev.delo.sh` is the `jev-litellm` LiteLLM proxy on big-chungus. `/typesafe/v1/systemone` is a pass-through to `api.typesafe.ai`; model `jev-latest` bills as `typesafe/jev-1.14.0`. Limits are enforced on it: LiteLLM runs `pre_call_hook` on pass-through endpoints, so `rpm_limit` raises `ProxyRateLimitError` (HTTP 429, header `retry-after: 60`, default `LITELLM_RATE_LIMIT_WINDOW_SIZE`) and an exhausted `max_budget` raises `budget_exceeded` (HTTP 422, the `litellm.budget_exceeded_status_code` default; the Jev config does not override it). Both were then observed live (section 6). The stale defaults pointed at `https://openrouter.ai/api/alpha/decisions` and `typesafe/jev-1.13`; the OpenRouter decisions endpoint is retired.

The probe turn used `thread_id`/`turn_id` strings, a UUID `correlationid` and `causationid`. Both the source turn and the produced annotation pass `core.validate.validate_envelope` (section 5).

## 12. Findings

1. The daprd > 1.13.0 requirement does not apply to the turn-enricher (no Dapr). It belongs to the embeddings enricher, which W8-3 does not deploy.
2. Clairic cannot run on the Mac: it needs a Cloudflare Workers AI token and account id, and the Mac has neither. They were not copied from Jarad's account and no token was minted. Running Jev-only is explicit and visible. If Damian wants typed facts (action, artifacts, blocker) he needs his own Cloudflare account (owner item).
3. The upstream defaults were stale (OpenRouter, jev-1.13); only compose overrode them. Fixed in `6b2a2bf`.
4. Jarad's live enricher uses the jev-litellm ingress/master key, not a dedicated virtual key. A dedicated key would give per-consumer spend and a revocable credential; not changed here (needs Jarad, and a restart of his container).
5. Live exposure note: this task minted two throwaway keys on Jarad's production Jev proxy through its admin API (using the ingress key) and deleted them within minutes. That is a production-system change under CHARTER 2; it was reversible and precedented by W0-5's mint of `damian-studio`, but Jarad may want to veto this pattern.
6. Process notes: a `pkill -f` pattern briefly matched Jarad's live enricher process on big-chungus (uid 10001); the kernel refused the signal, so nothing was killed (container still `Up 3 weeks`). The `perl alarm` wrapper did not stop a backgrounded `nats sub` on the Mac; it was removed by exact PID. No stray processes remain.
