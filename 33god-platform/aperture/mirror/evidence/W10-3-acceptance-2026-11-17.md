## 3. The instrument: `scripts/peer-check.sh`

What it is: one bash script (written for bash 3.2 and newer; run under bash 5 on big-chungus, and only parsed, not run, under the Mac's `/bin/bash` 3.2.57; needs `ssh` and `jq` locally; the peer needs only what a 33GOD Mac peer already has). `shellcheck -s bash -S style` is clean (v0.11.0). Exit 0 = no FAIL, 1 = FAIL, 2 = usage or ssh error. `--json` emits `{target, host, started, finished, summary, checks[]}`; the text lines go to stderr in that mode.

It is read-only with one allowed write: a tagged synthetic hook event (`session_id peercheck-probe-<epoch>-<pid>`, cli `opencode`, native `session.created`) is sent through `bb-hook` to the hook-hub socket from a throwaway directory, then looked up in the peer's Candystore. That is the same path `buttonup-bus-2026-11-17.md` section 3 used. Opencode `session.created` was chosen there because it selects no session-end writer, and no Hindsight bank was created by it (bank count stayed 5). The probe row stays in Candystore because there is no delete API. `PEER_PROBE=0` skips it.
