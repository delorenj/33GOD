## 2. Missed-fire policy

Chosen: **run at wake, coalesce, idempotent**, relying on Candybar AD-6 rather than a second manifest.

- **Missed 06:00** (Mac off, executor down): the latest missed fire runs once when the executor returns (`trigger=misfire`, same idempotency key as the scheduled fire). Earlier missed fires inside 24 h are recorded `skipped(misfire_coalesced)`, never replayed as a burst.
- **Overlap** is refused (`skipped(overlap)`).
- **DST:** a 06:00 wall-clock fire is never skipped or repeated by a transition (they happen at 02:00).
- **Idempotency, three layers:** the Candybar key per fire; `nightly.sh` verifies first (a valid published report is not regenerated); `DDR_DELIVER_ONCE=1` receipts plus Resend's `Idempotency-Key`. A retry, a misfire after a late fire, or a manual run therefore cannot send a second copy (proven, W9-2 section 4).
- **Edge:** a run that only happens at wake on a **later calendar day** reports the day before the wake day. The day it skipped appears as a gap in `report-delivery` in the next report; backfill with `nightly.sh nightly --date YYYY-MM-DD`.
- The Mac never sleeps (`pmset sleep 0`), so the normal case is a plain 06:00 fire.
- **No `on_failure`.** Damian has no alert destination (ntfy is W10-1, opt-in). A failure shows in `candybar history` and as the next morning's gap.

I did not add a separate "ensure" manifest (the repair-at-wake job big-chungus runs): AD-6 already runs the missed fire at wake and `nightly nightly` verifies first, so a second clock would only add a second path to the same send.

## 3. Candybar mechanics worth knowing

- `candybar register <dir>` is create-only; `enabled` is never synced, so it registers disabled and needs `candybar resume`. I did exactly that after the manual proof.
- `candybar next` prints only the single next fire across all candybars, so it showed `mac-hindsight-capture-sweep` (13:50), not this job. The 06:00 fire is not visible there until it is the soonest. The API has no per-candybar next-fire field in the response I read, so the first fire is confirmed only by `history` tomorrow.
- Cost is `unmeasured` until a scheduled run reports metrics; nothing to do.
