## 6. Findings

1. **`hermes.gateway-routing` already fails on live big-chungus** (api-direct host, `automaticai/auto*` routes not in the curated list). Unchanged by this task
   (default kept as ordered). Decision for Jarad, optional: either update the defaults in `host-overlay.ts` or drop an overlay on big-chungus that names the live gateway.
2. **The shell adapter does not consume the lane overlay yet.** `providers/plane.sh` `tp_cfg` (hermes-agent-template) reads role.yaml itself. Wiring it is one line,
   `flume lanes get "$ROLE_YAML" <band>`, but the template has 74 deployed copies and is a separate repo, so it was deliberately not edited. Until then the lane overlay is
   resolved and testable (`flume lanes show`) but a Mac transition still reads the tracked name. W6-3 should either carry that template change or give Damian role.yaml files
   with empty lane names.
3. **Adapter defaults need matching lanes on Damian's Plane**: bands the overlay leaves out resolve to `In Review` / `Needs Attention`; a board without them fails the transition.
4. **Other first-host literals remain, out of W6-2 scope** (W6-3's "no Jarad-owned values in rendered output" must handle them): `COMPANY_MAIL_DOMAIN = "agents.delo.sh"`
   (`workforce/validator.ts:58`, plus invite text in `workforce/plane.ts`), the `plane.delo.sh` hint in `hire/types.ts:82`, and the org/workforce data (W6-3 builds a fresh org).
5. `looksLikeSecret` is a tripwire (vendor prefixes, URL userinfo), not a scanner; the repo git guards remain the scanner.
