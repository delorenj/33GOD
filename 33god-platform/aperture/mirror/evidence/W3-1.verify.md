## 4. Preservation without a content baseline (Codex's second and third FAIL items)

W3-1 recorded no content hashes for HeyMa or skillex, because it never meant to touch them. Codex declined to rely on timestamps because "timestamps can be restored".

That is true of mtime (`utimes`), but not of ctime. The kernel updates a file's or directory's ctime on every write, create, delete (in the parent directory), rename, chmod or `utimes` call. It cannot be set from user space without root or changing the clock, and no sudo was available or used.

So these two results are a complete proof that no file was added, removed or changed in either tree from 15:31 EST onward, which covers the whole W3-1 window (15:32-15:44):

- `find ~/HeyMa ~/.config/vinyl -newerct '2026-11-10 15:31:00'` returns **0 entries**. That covers files and directories, so deletions would show too.
- In `~/code/skillex`, the same check returns only the two `.git` directories touched at 15:49:26 by the verifier. The index, refs and working files are unchanged.
