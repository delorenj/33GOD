## The resolver (upstream home: delonet-dotenv skill)

Existing `.env.op` tooling on DeLoNET is the `delonet-dotenv` skill (`~/code/skillex/all-skills/delonet-dotenv`, repo `delorenj/skills`); `~/.agents/scripts|bin` had nothing relevant. The resolver landed there:

- `delonet-dotenv/scripts/env-op-resolve.py` — stdlib-only, python ≥ 3.9 (runs on the Mac's `/usr/bin/python3` 3.9.6 under launchd's minimal PATH). Modes:
  - `render .env.op [out]` — resolves refs → atomic 0600 `.env` (temp file + rename; no partial output on failure)
  - `exec --env-file F -- cmd…` — injects resolved vars (file wins over inherited env, like `op run`) and `execvpe`s
  - `key <ref>` — prints the deterministic store key for a ref
- Deterministic key scheme: `op://Vault/Item/Field` → `OP_VAULT_ITEM_FIELD` (uppercase, non-alnum runs → `_`). refmap.tsv rows are **verified against the derivation on every run** — a disagreeing row, duplicate ref, or two refs mapping to one key all fail closed.
- **Fail closed** on: ref not in refmap, store key without value, duplicate keys in `.env.op` or store, malformed lines, embedded `op://` inside a literal. Errors name keys/refs only, never values.
- Multiline/special chars: store accepts double-quoted values with `\n \r \t \" \\` escapes; render emits the same form (compose/dotenv-compatible).
- `delonet-dotenv/tests/test_env_op_resolve.py` — 12 new tests (16 pass total in the suite).
- `delonet-dotenv/references/interim-store.md` + routing row in `SKILL.md`.
