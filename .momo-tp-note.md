# The Ticket Provider (tp) Adapter and Momo Agent

The `tp` (Ticket Provider) adapter is a strategy layer that maps normalized ticket states to specific providers like Plane, Linear, or Trello. It is **NOT** a standalone CLI executable.

### How it works:
1. **Source location:** The adapter is maintained in `hermes-agent-template/template/.scripts/lib/ticket-provider.sh`.
2. **Project-local installation:** When a project is scaffolded via `pjangler`/`CommonProject`, it is copied into that specific project's agent role directory (e.g., `<role_dir>/.scripts/lib/ticket-provider.sh`).
3. **Execution context:** `tp` is a bash function. Momo's scripts (like `momo-board.sh`) locate the `.project.json`, find the `role_dir`, source the script, and invoke the function.

### AI Agent Hallucinations
Because the Momo skill documentation states it "Drives Plane (via the repo `tp` adapter)", AI agents often hallucinate that `tp` is a standard terminal command in `$PATH` (e.g., trying to run `tp PLANE-123`).

**Agents must know:**
- Never execute `tp` as a bare CLI command.
- Even when sourced, `tp` expects an operation as the first argument, not a ticket ID (e.g., `tp get_issue PLANE-123`, not `tp PLANE-123`).
- `tp` is purely an internal engine mechanism used by Momo and Hermes to talk to providers.
